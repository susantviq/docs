Everything the **Automations** screens in the Vortex IQ app do with your automations is available over REST:
set an automation up from a template, schedule it, run it now, follow the run, and plan around the calendar. Drive
automations from your own tooling instead of the app. (Approving and rejecting a run's changes stays in the app.)

The API, and the login that gives you a token:

```
https://automations-api.vortexiq.ai/v1/automations
https://app.vortexiq.ai/v2/api/automations/login
```

Calls are authenticated as your Vortex IQ user and scoped to your organisation, with a **bearer token** from the
[Login](/automations/api/login) endpoint: your organisation's API credential plus your own identity, the same way
the [StagingPro API](/vortex-apps/staging-pro/api/overview) logs in. Stores are referenced by the
`integration_id` the API lists; their keys stay in Vortex IQ and never travel through your requests.
See [Authentication](/automations/api/authentication).

## A typical flow

<Steps>
  <Step title="Log in">
    [Log in](/automations/api/login) with your organisation's API credential and your identity to get a bearer
    token. Send it as `Authorization: Bearer <token>` on every call; log in again when it expires after an hour.
  </Step>
  <Step title="Know what you can set up">
    `GET /v1/automations/templates` lists the templates your organisation can use, each with `readiness`, and
    `GET /v1/automations/stores` lists your connected stores with the `integration_id` an automation runs on.
  </Step>
  <Step title="Set it up">
    `POST /v1/automations` with a `template_id`, an `integration_id`, the template's `inputs` and a `schedule`.
    With a schedule it is `active` at once; with `cadence: manual` it is a draft you run by hand.
  </Step>
  <Step title="Run it">
    The schedule queues runs by itself. To run now, `POST /v1/automations/{automationId}/runs` with an
    `idempotency_key`: you get the run back at once, `queued`.
  </Step>
  <Step title="Follow it">
    `GET /v1/automations/runs/{runId}` every few seconds while the run is `queued` or `running`, passing
    `after_seq` for just the new steps. A finished run carries its `summary` and `result`.
  </Step>
  <Step title="Plan around it">
    `GET /v1/automations/occurrences` gives the calendar of coming runs; move one or skip one with the endpoints
    beside it.
  </Step>
</Steps>

A run started through the API is a run like any other: the app's **Runs** screen shows it, with its steps and
findings.

## Automation states

| State | What it means |
| --- | --- |
| `draft` | Set up with a manual schedule, or an imported workflow with a step still unbound. Runs only by hand, which turns it on. |
| `active` | Turned on: its schedule, when it has one, queues runs, and one that starts on a store event runs when the store sends it. A manual automation becomes active after its first run. |
| `paused` | Its schedule is stopped, by you or after repeated failures (`paused_reason` says which), and its scheduled runs already queued are cancelled. You can still run it by hand. |
| `archived` | Nothing runs, and its queued runs are cancelled; its history stays readable. Restore brings it back paused. |

## Run statuses

| Status | What it means |
| --- | --- |
| `queued` | Waiting to start. |
| `running` | Running now. |
| `waiting_approval` | Waiting for someone to approve its changes in the Vortex IQ app. |
| `succeeded` | Finished. `summary` and `result` say what it found or did. |
| `failed` | Ended with an error; `reason_code` and `message` say why and what to do. |
| `refused` | Not started, for a reason in `message`, such as a disconnected store. |
| `cancelled` | Stopped by a person, or by an approval that expired. |
| `expired` | Ended without finishing, for a reason on Vortex IQ's side (`platform_fault`); it never counts against the automation. |

## Schedules

| Cadence | Runs |
| --- | --- |
| `manual` | Only when you run it. |
| `once` | On one `date` at `run_at`, then has no next run. |
| `hourly`, `every_6_hours` | Every hour, or every six hours. |
| `daily` | Every day at `run_at`. |
| `weekdays` | On the `days` you give (1 is Monday), Monday to Friday unless you say. |
| `weekly` | Every week on `day_of_week` at `run_at`. |
| `monthly` | On `day_of_month`, or on the `week_of_month` and `day_of_week` you give. |

Times are in the automation's timezone: its store's unless you set `timezone`. A scheduled run starts within ten
minutes after its time. [Preview schedule](/automations/api/preview-schedule) tells you the next three times before
you save anything.

## Who did it

Every automation and run records who made it and how, the way StagingPro records who started a migration:

| Field | Value |
| --- | --- |
| `created_by` | The person: the one you named at login, for anything made through the API. |
| `created_via` | `api-token` through this API, `ui` in the Vortex IQ app; null for a run the schedule queued. |
| `api_client_id` | Your credential's client id, for anything made through the API. |

## Safety

- **A credential never approves.** A run that would change your store waits for approval in the Vortex IQ app; the
  approve and reject endpoints refuse an API credential's token with `403`.
- **Everything is scoped to your organisation.** Another organisation's automation, run or import answers `404`
  when you name it in the path; as a filter it matches nothing (an empty list, or `422` on the calendar).
- **Changes need the version you read.** Update automation and moving a coming run carry a `version`; a stale one
  is refused with `409 stale_version`, so two tools never overwrite each other.
- **Run now is idempotent.** The same `idempotency_key` returns the same run, so a retried request never starts two.
  A key is one across all your organisation's automations: reused on another, it is refused with `422`.
- **Test runs change nothing.** `mode: test` reads your store for real and refuses every change.
- **Organisation switch.** While Automations are switched off for your organisation, every call answers `403`.
- **Limits.** Up to 600 calls a minute for each person and 3,000 for each organisation, for the API alone (the
  Vortex IQ app's own screens are counted apart), then `429` with `Retry-After`. The login allows 10 attempts a
  minute.
- **Stores are connected in the app.** Connect and disconnect stores in Vortex IQ (**Settings**,
  **Connected Sources**); this API reads them, never changes them.
- **Poll, do not stream.** There is no streaming endpoint: ask for a run again every few seconds while it runs.
