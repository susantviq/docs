## Monitor performance

10 performance signals. Signals with an alert band can raise Nerve Centre alerts; every signal supports a merchant-configured watcher.

| Signal | Outcome | Alert behaviour | What it tracks |
| --- | --- | --- | --- |
| **Hours Since Last Row Change** | Catalogue quality | Alert band 6 / 24 | Stale-table detector - hours since the most-recent row edit. >24h on a live ops table means the upstream feed has gone silent. |
| **Open Order-Exception Rows on Live Orders** | Protect revenue | Merchant rule | Manual order-exception queue rows that map to live, paid ecom orders still sitting unresolved - revenue stuck in a spreadsheet. Needs an ecom sibling + an order-id field  |
| **Empty Field Rate %** | Control risk and change | Alert band 2 / 15 | Share of field values left blank across the sampled rows (up to the 200-row page cap), measured against every column returned by the Fields API. |
| **Field Count** | Run operations | Watch only | Number of columns on the monitored table - baseline for schema-drift detection. |
| **Freshness Lag (minutes)** | Run operations | Alert band 60 / 1440 | Same stale-table detector as Hours Since Last Row Change, in minutes - the byo_data_source archetype's freshness_lag band is minutes. |
| **Open-Status Rows** | Run operations | Alert band 10 / 50 | Rows whose status is not in the done set - the unactioned queue (returns / order exceptions). Gated on a configured status field. |
| **Row Count** | Run operations | Watch only | Total rows in the monitored table - from the `count` field on the list-rows response. |
| **Rows Added (24h)** | Run operations | Merchant rule | New rows in the last 24h - needs a Created-on field on the table (Baserow does not expose row creation time otherwise). |
| **Saved Views** | Run operations | Watch only | Number of saved views (grid / gallery / form / kanban / calendar) on the table. |
| **Tables in Database** | Run operations | Watch only | Inventory of tables in the parent database - id, name, row count. Gated on a configured database_id. |

## Audit risks and opportunities

A fix status appears only where the action, inputs, approval, verification and recovery controls are mapped. Candidate remediations are never executable.

| Check | Severity | Outcome | Why it matters | Fix status |
| --- | --- | --- | --- | --- |
| **Data-source API token invalid or access revoked** | critical | Control risk and change | Once this token fails, VortexIQ stops pulling data from this source entirely, and every card and finding built on it goes stale from that moment, silently, until someone notices the numbers  | Report only |
| **Source not updated in over 24h (stale data)** | high | Run operations | A source that has not updated in over a day means every conclusion drawn from it describes yesterday; the staleness is invisible unless surfaced. | Report only |
| **Required-field empty rate above 15%** | medium | Catalogue quality | When required fields are empty in more than 15 percent of rows, every downstream calculation inherits the gaps and quietly under-reports. | Report only |
