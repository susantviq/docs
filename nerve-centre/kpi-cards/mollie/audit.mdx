Mollie state matters when it's tied to captured revenue and checkout friction. This audit answers: (1) is the API key valid and the environment (test/live) correct, (2) is the success rate holding and which method (iDEAL / card / Bancontact) is driving declines, (3) are refunds, chargebacks and settlement timing under control, and (4) does payment friction map to lost revenue and support load via the commerce + support siblings.

## What this audit checks

### Authentication & access
- API key valid (probe on /v2/organizations/me)
- Key environment matches intent (live_ in production, test_ in sandbox)
- Key returns data for payments, settlements, refunds and chargebacks

### Transaction health
- Success rate below 90%
- Decline rate above 8% (and which failureReason codes dominate)
- A payment method authorising below 85% (rail-specific breakage: iDEAL vs card vs Bancontact)
- 3DS / SCA challenge abandon rate above 30% (added friction / abandonment risk)

### Refunds & disputes
- Refund rate above 8% of volume
- Chargeback rate above 0.9% (network monitoring-programme threshold)
- Dispute / chargeback count spiking versus the 7-day baseline
- A high-share regional method (iDEAL, Bancontact) deactivated or pending-review while still receiving traffic

### Settlement timing
- Average settlement time above 5 days (cash-flow risk)
- Oldest pending payout above 5 days
- A settlement in failed status

### Cross-channel: payments-to-revenue (the killer area)
- Failed-payment shoppers opening support conversations (sibling support_helpdesk) - friction driving support load
- Mollie captured volume vs commerce-sibling order revenue mismatch > 2% (reconciliation gap)
- Refund spike correlated with a commerce returns spike in the same window
- Decline-rate spike during a campaign push (paying for traffic that can't pay)

## Data sources

- `GET https://api.mollie.com/v2/payments` - Volume / success / decline / method mix / decline reasons / 3DS abandon
- `GET https://api.mollie.com/v2/settlements` - Settlement timing / pending payout age
- `GET https://api.mollie.com/v2/refunds` - Refund rate / refund volume
- `GET https://api.mollie.com/v2/chargebacks` - Chargeback rate / dispute rate / reason mix
- `GET https://api.mollie.com/v2/methods` - Enabled payment methods / regional-method status
