## At a glance

{/* HUMAN_AUTHORED:tldr */}
> Revenue split by transaction Currency Code. Highlights FX exposure on multi-currency Companies.

| | |
| --- | --- |
| **What it counts** | `SUM(G/L Entry.Amount LCY)` grouped by `Currency Code` from the originating Sales Invoice / Cash Receipt. |
| **Tax treatment** | Net of VAT. |
| **Currency** | Both transaction-currency total and Reporting Currency equivalent shown. |
| **Time window** | `30D` |
| **Alert trigger** | `-` |
| **Roles** | owner, finance |

## Worked example

{/* HUMAN_AUTHORED:worked_example */}
UK apparel parent on BC, 30D window 14 Mar to 12 Apr 26. Reporting currency GBP.

| Currency | Revenue (transaction) | GBP equivalent | % of total |
| --- | --- | --- | --- |
| GBP | £2,640,000 | £2,640,000 | 54% |
| USD | $1,820,000 | £1,423,240 | 29% |
| EUR | €1,140,000 | £973,560 | 20% |
| AUD | A$420,000 | £218,400 | 4% |
| Less: elimination | (£366,400) | (£366,400) | -7% |
| **Total** | | **£4,888,800** | 100% |

USD = 29% of revenue → 1% USD movement = ~£14K monthly P&L impact. Treasury can size FX hedges from this view.
{/* /HUMAN_AUTHORED:worked_example */}

## Known limitations / merchant FAQs

{/* HUMAN_AUTHORED:faqs */}
**Single-currency Companies?**
Card hides if only one Currency Code present.

**Local Currency vs Reporting Currency?**
Card shows both. Local is where the transaction posted; Reporting is the consolidated view.

**FX hedging input?**
Yes, Treasury teams use this card to size monthly FX hedges by exposure.

**Currency Exchange Rate cadence?**
BC's Currency Exchange Rate table holds daily rates by default. The Adjust Exchange Rates batch can revalue for reporting.

**Crypto / non-standard currencies?**
Excluded by default. Configurable.
{/* /HUMAN_AUTHORED:faqs */}
