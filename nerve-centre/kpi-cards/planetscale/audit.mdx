The questions every PlanetScale operator asks at 9am on Monday: which query patterns are reading the most rows (rows-read is the billed metric, so query efficiency is a direct cost lever), is row-read / write / storage usage burning toward the plan cap before the billing period ends, is any deploy request stuck open and not yet applied to production (schema drift / stalled migration), are branches and replicas healthy, and how stale is the last backup. Cross-references ecommerce platforms - a row-read storm or slow query co-occurring with a checkout drop, or product-table row-count drift vs the ecom catalog, indicates a database bottleneck or sync failure costing revenue.


## What this audit checks

### Authentication & access
- Service token authenticates over the REST API ('Authorization: <token_id>:<token>') without a 401 / 403
- Token has read_database + read_branch + read_deploy_request grants on the monitored database - APIs return rows, not permission errors
- Organization slug + database name resolve to a real, ready database (database.state = ready)
- Insights read access present where Insights is enabled (query-statistics cards otherwise gate off)

### Query Efficiency & Insights
- p95 query latency >200ms sustained 15m (Insights query statistics)
- Slow-query rate >5% of executions over the slow threshold (Insights deltas)
- A query pattern reads a disproportionate share of total rows (high rows-read-per-execution = missing-index / full-scan candidate; PlanetScale-distinctive billed-cost driver)
- Rows-read-per-query trend climbing >baseline (query regression silently inflating the bill)

### Usage vs Plan & Cost
- Row reads in the billing period >90% of the plan row-read cap (overage / throttle imminent)
- Row writes in the billing period >90% of the plan write cap
- Storage used >90% of the plan storage cap (table growth outpacing cleanup)
- Rows-read run-rate projects to exceed the cap before the billing period ends (burn-rate extrapolation)

### Schema Workflow (Branches & Deploy Requests)
- Deploy request open >24h not yet deployed to the production branch (stalled migration / schema drift; PlanetScale-distinctive)
- Deploy request in errored state during apply (failed schema migration needing attention)
- Stale dev branch not deleted / merged (branch sprawl - each branch carries storage + connection overhead)
- Production branch not in ready state OR a branch failed to provision

### Capacity & Backup
- Connection saturation >90% - open connections / branch connection cap (connection-refused errors imminent)
- Last successful backup older than 72h on the production branch (MAX(completed_at) where state=success)
- Backup in state=failed in the last 7 days (recovery window at risk)
- Read replica / read-only region lag elevated where read replicas are configured

### Cross-channel: database vs ecommerce reconciliation
- Slow query or row-read storm co-occurs with an ecom checkout drop in the same 5-min window (sibling = bigcommerce.checkout / shopify.checkout)
- Row-read spike with no matching ecom order spike (= bot / scraper / runaway job burning billed reads, sibling = bigcommerce.order / shopify.order)
- Connection saturation >90% during an ecom traffic burst (app gets connection-refused errors)
- Product-table row count drifts vs ecom catalog product count (sync failure, sibling = bigcommerce.product / shopify.product)

## Data sources

- `GET /organizations/{organization}/databases/{database}` - Database state, plan, region, sharded flag
- `GET /organizations/{organization}/databases/{database}/branches` - Branch inventory - production + dev branches, ready state
- `GET /organizations/{organization}/databases/{database}/branches/{branch}` - Branch detail - ready state, cluster / connection metrics
- `GET /organizations/{organization}/databases/{database}/branches/{branch}/cluster` - Connection usage / saturation for the branch cluster
- `GET /organizations/{organization}/databases/{database}/deploy-requests` - Deploy-request lifecycle - open / stuck / errored schema changes
- `GET /organizations/{organization}/databases/{database}/insights` - Query statistics - per-query p95 latency + rows read / written (plan-gated)
- `GET /organizations/{organization}/databases/{database}/usage` - Billing-period usage - rows read / written, storage vs plan caps
- `GET /organizations/{organization}/databases/{database}/branches/{branch}/backups` - Backup recency + state per branch
- `GET /organizations/{organization}/databases/{database}/branches/{branch}/keyspaces` - Sharding topology (Vitess keyspaces) for sharded databases
