## At a glance

{/* HUMAN_AUTHORED:tldr */}
> Klarna does not use 3DS card-style authentication. Klarna's own consumer-authentication flow (one-tap Klarna app login or email-OTP) replaces it. This card tracks **Klarna-app-authentication abandonment**: customers who started the Klarna login flow but didn't complete.

| | |
| --- | --- |
| **What it counts** | `COUNT(initiated Klarna auth) - COUNT(completed)` divided by `COUNT(initiated)`. Klarna-app-flow specific. |
| **Healthy baseline** | 8-15% abandonment is normal. |
| **Mobile vs desktop** | Mobile abandons less (Klarna app installed); desktop higher (email-OTP friction). |
| **Time window** | `7D vsP`. |
| **Alert trigger** | `>30%`. |
| **Sentiment key** | `gauge_inverse: good<=15, warn>30` |
| **Roles** | owner, operations |
{/* /HUMAN_AUTHORED:tldr */}

## Known limitations / merchant FAQs

{/* HUMAN_AUTHORED:faqs */}
**Klarna doesn't use 3DS, why this card?**
The card is named for the archetype (3DS-style authentication abandonment); for Klarna it tracks Klarna-app or email-OTP authentication abandons. Same shape, different mechanism.

**Why is mobile so much better than desktop?**
Klarna app one-tap login on mobile; desktop requires email OTP which has 30-90 second delivery delay and inbox-finding friction.

**Email-OTP delivery problems, can I fix?**
Klarna delivers OTPs from a Klarna-controlled domain. Merchants cannot influence delivery; ask Klarna support if delivery rates are anomalous.

**Cart-recovery for Klarna abandoners?**
Yes; cart-recovery email after 1 hour recovers 10-18%.
